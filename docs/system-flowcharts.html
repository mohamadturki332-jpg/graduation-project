IT Help Desk Ticket System — Flowcharts & Ticket State Machine

The core flows of the system: how a request becomes a resolved ticket (through either the web form or email), and how a user is authenticated with the two-factor sign-in. Each flowchart shape marks a kind of step; each diamond is a decision. The final figure is a state diagram — it shows the seven statuses a ticket can hold and which moves between them are allowed.

1  Ticket lifecycle

From the moment a user needs help to a closed, rated ticket. A request enters through one of two channels, both of which converge on a single created ticket that a technician then works to resolution.

Figure 5.2 — Ticket lifecycle: two intake channels converge on one created ticket, which a technician drives to resolution.

2  Login & two-factor authentication

Every sign-in passes three gates — a brute-force limit, the password check, and (for real email accounts) a one-time code sent by email — before the user is routed to the dashboard for their role.

Figure 5.3 — Login flow: rate-limit gate, password check, and email one-time code, ending in a role-based redirect.

3  Ticket state machine (the seven statuses)

Unlike the flow above, the statuses are not a straight line. A ticket sits in one state at a time; the four active states can be moved between freely, and the three terminal states permanently lock it. This is why the lifecycle flowchart keeps the ending simple — the real status logic is a state machine, shown here.

Rounded box = a status the ticket can hold Green dashed group = active states (freely interchangeable) Green / slate / rose = the three terminal outcomes
